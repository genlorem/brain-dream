## 2. Диагноз

Сон пишет отчёт, у отчёта нет адресата. Три дефекта, каждый виден в числах:

1. **Нет памяти о сказанном.** Дедуп ищет точный хеш, перефразировка проходит как новое (53 %
   повторов). Сон не видит, что уже решено (15 %).
2. **Нет исполнителя.** 58 % действий требуют владельца, 38 % агент сделал бы сам; ни те, ни
   другие никуда не уходят. Действие часто без проверки (35 % «не проверить»).
3. **Нет сигнала правды.** Ручная оценка мертва дважды: кнопки не шлются, а когда слались —
   16 нажатий за два месяца. Строить обратную связь на нажатиях владельца нельзя.

## 3. Механика v2: журнал дел

Единица работы — **дело** (`case`): одна тема с устойчивым id, доказательствами по ночам и
машиной состояний. Находка ночи либо заводит дело, либо добавляет факт в существующее.

```
new ──► routed:agent ──► (сессия) ──► verifying ──► closed
   │                                       ▲
   ├──► routed:owner ──► (карточка) ───────┘
   │          └─► «Это шум» ──► dropped
   ├──► known (решено до сна) ──► dropped
   └──► watch (не к действию: держим в Brain, без адресата)
```

Хранилище — `~/brain/dreams/cases.jsonl` (append-only события, текущее состояние — свёртка),
пишет только оркестратор сна. В Brain — нода `case:<id>` при переходе в `routed`, ребро
`derived-from dream:<date>`; решения и уроки, закрывшие дело, ссылаются на неё.

**Ночь по шагам:**

1. **Сбор** — как сейчас, плюс в контекст генерации идёт список открытых дел (заголовок + последний
   факт): модель ищет новое, а не пересказывает известное.
2. **Генерация** — как сейчас (Sonnet), число проходов уменьшить до 30, когда гейты §4 срежут
   повторы (решение после замера в shadow).
3. **Гейты Jev** над каждым кандидатом (§4): к какому делу относится, решено ли до сна, кто
   исполнитель, цена бездействия, есть ли проверка.
4. **Синтез** — только по прошедшим гейты; формат дела обязательный: *что не так · действие ·
   проверка исхода* (команда, запрос в Brain или дата), без проверки дело не заводится.
5. **Маршрут:**
   - `agent` — обратимое действие в своей зоне (код, конфиг, Brain, процедура) → спарк-сессия
     через session-manager `--feedback`, та же механика, что у кнопки пропозалов; потолок 2 за ночь.
     Командные репо Travelmart/persona — только отчёт без коммита (правило коммитов).
   - `owner` — деньги, люди, юр. вопросы, физическое → одна карточка через мост digest-bot
     `POST /secretary-card` (кнопки «Принял / Сделай задачу / Это шум» уже есть у секретаря);
     потолок 3 в сутки; повтор карточки по делу только при новом факте или росте цены бездействия.
   - `watch` — остаётся находкой в Brain без адресата.
6. **Проверка исхода** каждую ночь по открытым делам: запуск проверки из дела (команда только из
   белого списка читающих), поиск в Brain решений/уроков с даты дела, затем Jev «решено ли по этим
   фактам» (§4). Закрыто → событие `closed` с доказательством. Дело без движения 14 дней →
   эскалация уровнем выше (agent → owner) или `watch`.
7. **Отчёт** — одна строка в Telegram утром: «закрыто N, новых M, карточек K, ждут владельца L»
   плюс раздел «Сон» в session-manager показывает журнал дел вместо топ-10.

## 4. Где Jev, где нет

Jev — классификатор с вероятностями ($0.042 за 1 млн входных токенов, ~300 мс, текст не пишет;
`note:jev-typesafe-what-it-is-and-when-to-use`). Подходит каждому вопросу с закрытым ответом.

| Вопрос | Тип | Вход (state) | Чем заменяет |
|---|---|---|---|
| К какому делу относится кандидат | Choice: 5 ближайших по эмбеддингу дел + «новое» | кандидат + 5 карточек дел | точный хеш (53 % повторов) |
| Решено ли это до сна | Noul | кандидат + решения/уроки Brain после даты источника (top-5) | ничего (15 % шума) |
| Кто исполнитель | Choice: agent / owner / watch | кандидат + действие | ничего |
| Цена бездействия | Score, 4 уровня словами | кандидат | метка obvious/non-obvious |
| Есть ли проверяемое действие | Noul | действие + проверка | ничего (35 % не проверить) |
| Закрыто ли дело | Noul | дело + свежие факты проверки | ничего |

Все вопросы над одним state считаются за цену одного запроса. Ночь — ≈ 100 кандидатов + ≈ 30
открытых дел, по ~3k токенов: меньше $0.02 в сутки.

Где Jev не годится: генерация и синтез (пишет текст — Sonnet), сравнение дат и чисел (в коде),
единственный гейт перед действием (спавн и карточка идут только при согласии правила кода
и Jev; при отказе Jev — прежнее поведение, fail-open).

**Правила из прошлых пилотов** (калибровка немонотонна, SKVO 222 кейса): своя кривая надёжности
на каждый вопрос, shadow до ≥ 30 размеченных случаев и ≥ 90 % согласия; инструкции и критерии
по-английски, state как есть. Правда для кривых есть уже сейчас: 320 находок окна и 40
размеченных случаев §1; недостающие метки — агент `jev-truth-labeler` по слепому листу.
Клиент — по образцу `session-manager/scripts/dm-replay/jev.py`, ключ `~/.config/typesafe/env`.
